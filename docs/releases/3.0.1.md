# Python connector 3.0.1

This version includes the changes tested in 3.0.1rc1 through 3.0.1rc4.

- Set `enable_result_batch_v2=True` to receive larger result batches, download
  serialized batches continuously, and decode chunks in parallel. The flag stays
  off by default. Both sync and async connections support it.
- Downloading continues while decoding runs. Each query has one result RPC in
  progress at a time. Rows and original chunk boundaries keep their order.
- Send and receive message limits default to unlimited (`-1`), including when
  V2 is off. Explicit application limits still apply.
- If a decode worker exits or its pipe breaks, the connector can decode the
  retained batch once in the parent process after stopping the failed workers.
  This uses the original deadline and makes no extra result RPC. Invalid data,
  cancellation, and expired deadlines still fail.
- Only the V2 `UNIMPLEMENTED` RPC error permits fallback to V1. Other RPC errors
  reach the caller unchanged. Queries and result RPCs are not replayed.
- Concurrent callers share a cluster auto-resume result. Waiting for the local
  resume lock no longer causes an early failure while a resume is still running.
- Debug logs include batch, download queue, and decode recovery details without
  logging result values or credentials.

## Use and limits

V2 requires planner support and `ENABLE_GET_NEXT_RESULT_BATCH_V2=true` on the
planner. The optimized client path supports ordinary GIL-enabled CPython 3.11
through 3.13. Keep application startup inside `if __name__ == "__main__":`.
See the [V2 usage guide](../../README.md#opt-in-multi-chunk-result-batches).

The serialized download queue has no size limit. It can hold the whole result
and exhaust client memory. Worker processes add memory and copying costs.
Parallel decoding does not promise a speedup for every result. Existing query,
RPC, and fetch timeouts remain in effect. Customer-scale completion within
900 seconds has not been established by the offline tests.

To disable V2, close existing work and create connections with the flag off.
This does not restore finite message-size defaults. Set explicit limits or
return to the previous connector version when those defaults are required.
