# Python connector 3.0.1 - validation

Validated on 2026-10-08. Base: `df85f81868aab047043b18a0eedf373fb2aae680`
(current `origin/main`). The RC4 source at `5455159` already includes this base.
Release preparation changes the package version, adds release documentation,
and fixes sync handling of prefixed gRPC options when V2 is off. V2 stays off
by default. Continuous downloading and decoder behavior are unchanged.

The independent review found that disabling V2 silently ignored sync limits
configured with `grpc.` prefixes. The existing option-name normalization was
inside the V2 condition. It now runs for both flag values, and conflicting
aliases are rejected for both. No download or decoder code changed.

Before the fix, real local gRPC regression tests produced **4 failures and 8
passes**: prefixed send/receive limits and conflicting aliases failed with V2
off. After the fix, the message-limit and sync/async V2 suites passed **141
tests**. The final suite also checks matching duplicate aliases and preservation
of the caller's options dictionary. No new mock or fake was introduced. This
report does not claim a new mutation test of every earlier requirement.

## 2. Regression risk

The full suite covers default-off V1 behavior, V2 buffers, sync and async APIs,
OAuth/session handling, routing, pools, SQLAlchemy, generated wire contracts,
and real local gRPC and decoder processes. The new transport regression tests
exercise both feature-flag values. See `test/unit/test_sync_result_batch_v2.py`,
`test_async_result_batch_v2.py`, `test_sync_result_prefetch.py`, and
`test_async_result_prefetch.py`.

## 3. Edge cases

Existing tests cover empty batches, malformed chunks, ordered publication,
cancel/close races, deadlines, process exit, broken pipes, decimal state, and
retained batch cleanup. `test_decode_worker_recovery.py` checks that recovery
uses the same deadline and prevents publication after cancellation.

## 4. Failure scenarios

Only V2 `UNIMPLEMENTED` falls back to V1. Other RPC failures reach the caller.
Worker transport failures can trigger one local decode of retained bytes after
worker cleanup. They do not replay an RPC or stop continuous downloading.
Malformed data and decoding errors remain fatal. These contracts are covered by
the V2, prefetch, and parallel decoder suites. Live service failure and planner
version combinations were not rerun against a customer engine.

## 5. Security

There are no new dependencies, authentication paths, endpoints, or credentials.
The fix preserves explicit message limits across a V2 flag rollback instead of
silently using unlimited defaults. Existing diagnostics and worker-boundary
tests run in the full suite. Package/source parity and metadata checks are
performed separately before the PR is updated. Offline tests do not establish
the security configuration of a customer deployment.

## 6. Observability

Existing `debug=True` batch, queue, and recovery diagnostics remain unchanged.
`test_result_batch_diagnostics.py` covers logging levels, counters, and sensitive
value handling. Connector debug logs do not guarantee that optional planner
diagnostic logs are enabled. No new metrics or planner changes are included.

## 8. Remaining risks

The uncapped serialized queue can exhaust client memory. This is the explicitly
requested tradeoff for downloading as soon as possible. Unlimited message-size
defaults also apply when V2 is off; applications may set explicit limits.
Parallel decoding can add startup, copying, and memory costs. The offline suite
does not qualify customer-scale performance or the original 900-second target.
See [release notes](3.0.1.md) for runtime prerequisites and rollback behavior.
