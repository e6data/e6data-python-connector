## 2. Regression risk

The full suite covers default-off V1 behavior, V2 buffers, sync and async APIs,
OAuth/session handling, routing, pools, SQLAlchemy, generated wire contracts,
and real local gRPC and decoder processes. Release preparation does not change
these paths. See `test/unit/test_sync_result_batch_v2.py`,
`test_async_result_batch_v2.py`, `test_sync_result_prefetch.py`, and
`test_async_result_prefetch.py`.

## 3. Edge cases

Existing tests cover empty batches, malformed chunks, ordered publication,
cancel/close races, deadlines, process exit, broken pipes, decimal state, and
retained batch cleanup. `test_decode_worker_recovery.py` checks that recovery
uses the same deadline and prevents publication after cancellation.

## 4. Failure scenarios

Only V2 `UNIMPLEMENTED` falls back to V1. Other RPC failures reach the caller.
Worker transport failures can trigger one local decode of retained bytes after
worker cleanup. They do not replay an RPC or stop continuous downloading.
Malformed data and decoding errors remain fatal. These contracts are covered by
the V2, prefetch, and parallel decoder suites. Live service failure and planner
version combinations were not rerun against a customer engine.

## 5. Security

There are no new dependencies, authentication paths, endpoints, credentials, or
runtime changes in release preparation. Existing diagnostics and worker-boundary
tests run in the full suite. Package/source parity and metadata checks are
performed separately before the PR is updated. Offline tests do not establish
the security configuration of a customer deployment.

## 6. Observability

## 8. Remaining risks

The uncapped serialized queue can exhaust client memory. This is the explicitly
requested tradeoff for downloading as soon as possible. Unlimited message-size
defaults also apply when V2 is off; applications may set explicit limits.
Parallel decoding can add startup, copying, and memory costs. The offline suite
does not qualify customer-scale performance or the original 900-second target.
See [release notes](3.0.1.md) for runtime prerequisites and rollback behavior.
